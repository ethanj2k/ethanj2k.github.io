Privacy Policy — Last Word: Comment & Participant Fields for Jira

Effective: 27 November 2026

Last Word: Comment & Participant Fields for Jira ("the app") is published on the Atlassian Marketplace by Two Little Moons Consulting, ABN 49 732 400 198, Penrith, NSW 2750, Australia ("we", "us"). Contact: support@twolittlemoons.com.

This policy is specific on purpose: every category of data the app touches is itemised below.

What the app does

The app keeps eight read-only custom fields up to date on each work item — who has taken part, who commented last and when, how many comments and attachments it has, and when it was first answered — and shows a message an administrator writes on the create screen. It runs entirely on Atlassian's Forge platform and sends data to no server outside Atlassian.

Data the app reads from Jira

When a comment is added, edited or deleted, an attachment is added or removed, a work item is created, or its reporter or assignee changes — and when an administrator fills in existing work items from the admin page — the app reads, for that work item:

  • its id and key;
  • the account ids of its reporter and assignee;
  • for each comment: the author's account id and account type (person, portal customer or app), when it was written, whether it is restricted to a role or group, and whether it is a Jira Service Management internal note. The app does not read or keep what a comment says;
  • the number of attachments (Jira returns the attachment list; the app counts it and keeps nothing else from it);
  • the values this app has already stored in its own fields, so it writes only what changed;
  • the list of custom fields, to find the ids of this app's own fields;
  • for the Message field, the text an administrator saved in that field's context configuration, for the project and work type of the form being shown.

On the admin page the app also reads the administrator's permissions (/mypermissions) to check they administer the site, and asks Jira to count the work items in a scope they enter. Reads that run in the background are made as the app; their result is a field value Jira permission-checks on read like any other.

Data the app writes to Jira

  • the computed values, into the app's own read-only custom fields on the work item. A Forge app may only write the values of fields it owns, so the app can change no other field. These writes add nothing to the work item's history.

Data the app stores

In Forge storage, inside your own Atlassian site, one document: the progress of a fill-in run started from the admin page — the JQL scope the administrator entered, an opaque page token, counts of work items read and changed, its state and when it started and last progressed. Nothing is stored per work item and nothing about any person. The Message field's text is stored by Jira itself, in the field's context configuration.

Data visibility

A computed value is an ordinary Jira field value, so anyone who can see the work item can see it, exactly as they can see its other fields. For that reason the app counts only public comments: a restricted comment or an internal note never contributes to any value, so its author and timing cannot be learned from these fields.

Data leaving Atlassian

None. The app declares no permissions.external of any kind: no fetch, no egress, no remote host and no analytics. It is not technically capable of contacting any host other than Atlassian's own APIs.

Logging

The app writes operational log lines to Atlassian's Forge logging: event types, work item ids and keys, counts, and the status of a failed Jira request. It does not log field values, account ids, comment content, the administrator's scope, or the bodies of Jira's responses.

Retention and deletion

The fill-in progress document lives in Forge storage inside your site and is destroyed when the app is uninstalled. The values already written remain on your work items as field values until the fields are removed in Jira's custom field administration.

Your rights

Because the app stores everything inside your own Atlassian site and sends nothing elsewhere, requests about personal data — access, correction, erasure — are answered by your own Atlassian administration. Write to support@twolittlemoons.com if you need help identifying what the app holds.

GDPR and CCPA

We are a data processor, not a data controller, and a service provider, not a business. We process End-User Data only inside Atlassian apps and services, on your instructions, and we share it with no third party.
