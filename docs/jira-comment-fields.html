Last Word: Comment & Participant Fields for Jira

The support-desk fields Data Center's Toolkit gave you — Participants of an issue, Last commented by, Days since last comment, Number of comments and the rest — on Jira Cloud, under the same names. Your migrated filters and dashboards read the same. One edition, everything included, US$0.65 per user per month, free for ten users or fewer.

Atlassian's Toolkit for Jira has no Cloud version and no migration path. The Cloud alternatives charge $0.72 (Comment Custom Fields) and $1.00 (Jira Misc Custom Fields) per user.

Getting started

1. Install

Install from the Marketplace listing, or in Jira go to Apps → Explore more apps and search for Last Word. You need to be a Jira administrator.

2. Put the fields on your screens

The eight fields exist as soon as the app is installed. Go to Settings (cog) → Work items → Screens (or a team-managed project's own field settings) and add the ones you want, exactly as you would any custom field. They are read-only: the app keeps them up to date and nobody types into them.

3. Fill in the work items you already have

Go to Settings (cog) → Apps → Last Word: Comment & Participant Fields for Jira. Leave the scope empty for every work item, or narrow it with JQL such as project = SUP, choose Count work items to see how many that is, then Start. The page shows its progress as it goes. New comments, attachments and changes of reporter or assignee update the fields on their own from the moment the app is installed.

4. Add a message to a create screen (optional)

Go to Settings (cog) → Work items → Custom fields → Create custom field, choose Message Custom Field (for edit), and add it to a create screen. Open the field's context and write the message there — a title, plain text and an appearance. A different message per project or work type is just another context.

Searching

"Participants of an issue" = currentUser()
"Last commented by a User Flag" = "true" AND statusCategory != Done
"Days since last comment" < -7d
"Number of comments" > 20

true is a reserved word in JQL, so the User Flag is compared with "true" in quotes.

If something looks wrong

  • A field is empty on an older work item. It predates the install; fill it in from the admin page (step 3).
  • A value did not change straight away. Values land within seconds of the change, not in the same keystroke. Reload the work item.
  • A comment did not count. Only public comments count. A comment restricted to a role or group, or a Jira Service Management internal note, never does.
  • Still stuck? Write to support@twolittlemoons.com.

"Number of comments" > 20, "Participants of an issue" = currentUser() and "Last commented by a User Flag" = "true" AND statusCategory != Done work exactly as written.

Right in JQL the moment it changes — no reindex

The Toolkit computed its values when Jira indexed a work item, which is why its own reviews say "Participants Field is not returning correctly in JQL searches … after the project reindex it's showing the correct result."

This app stores each value in Jira's index the moment a comment is added, edited or deleted, an attachment comes or goes, or the reporter or assignee changes. Boards, filters, dashboards, JQL and CSV exports all see it straight away, and nothing is worked out at search time.

Days since last comment was never searchable in Data Center. Here it is stored as the date of the last public comment and displayed as days, so it is right on screen every day and exact in search: "Days since last comment" < -7d finds everything quiet for more than a week.

A Message field that does not break the create screen

The Toolkit's Message field is the subject of most of its bad reviews: HTML that is forgotten the next time you edit it, a field that breaks the page layout, a message that never appears. Here the message is plain text written in Jira's own field context screen — so a different message per project and work type is just another context — and it is shown as a standard Atlassian notice. The field holds no value and answers the create dialog immediately, so it never slows a create down.

Existing work items filled in, on your terms

New activity updates the fields on its own. For work items created before the app was installed, the admin page counts any JQL scope you give it and fills those work items in — every work item if you leave it empty — and shows its progress as it goes.

Quiet by design

  • No history noise. These values are derived, so writing them adds nothing to a work item's history — no "Number of comments 4 → 5" burying the real changes.
  • Nothing runs for events that cannot change a value. Editing a summary, a label or a status never invokes the app at all; only comments, attachments, new work items and changes of reporter or assignee do.
  • Runs on Atlassian. No egress, no remote backend, no analytics. The app cannot contact any host other than Atlassian's own APIs, and everything stays in your site.

What it does not do, said before you buy

  • Public comments only. A comment restricted to a role or group, or a Jira Service Management internal note, never counts toward any field. These are ordinary field values that anyone who can open the work item can read, so a restricted comment's author and timing must not leak through them. (Data Center worked "Days since last comment" out per viewer; a stored Cloud value cannot be.)
  • "Last commented by a User Flag" is defined for Cloud. Data Center meant "not in the jira-developers group", which Cloud does not have. Here it is true when the last public comment came from the reporter or a portal-only customer.
  • "Days since last comment" is searched as a date (< -7d), not as a number (> 7). A saved filter that used the number form needs that one change.
  • Comments written by an app (Automation rules, bots) count in "Number of comments" and the dates, but never become the last commenter, the first response or a participant — an auto-reply is not somebody answering.
  • Participants holds up to 100 people, Jira's limit for a list field. The reporter and assignee are never the ones dropped.
  • Values land within seconds of a change, not in the same keystroke.
  • Not included: "Domain of Reporter" and "Domain of Assignee" (Cloud hides email addresses by default), "Username of last updater or commenter", "User Property Field" and "Message Custom Field (for view)".
  • Not Cloud Fortified. That is a Marketplace programme a vendor applies to once an app has install volume and a support history. Runs on Atlassian — the technical bar underneath it — is met from day one.
